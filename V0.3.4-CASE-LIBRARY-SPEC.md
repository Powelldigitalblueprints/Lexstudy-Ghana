# LexStudy v0.3.4 — Case Library: spec

**Status: APPROVED by Abdul 2026-11-14 (widget tap + message). Build the Case
Library now; the paid gate is built into the code but switched OFF until
payments connect. Built 2026-11-14 as v0.3.4 (gate off by default); this file
remains the contract the build followed.**

## 1. What it is

A new section, `/library`, where a student can search for a case and get
everything they need for it: facts, holding, ratio decidendi, and the rest
of the file below. It is the paid section of the site. While payments are
not connected the gate stays off and the library is open to everyone; one
environment switch gates it when payments land (see §4).

The existing `/cases` brief library is NOT changed. Free tier keeps the
IRAC summaries there; the Case Library holds the full case files.

## 2. Case-file schema (exact — the draft must match this)

One Python list, `CASE_FILES`, in a new module `case_library.py`. One dict
per case, these keys, no others:

```python
{
    "slug": str,               # MUST equal the verified brief slug in verified_cases.py
    "title": str,              # e.g. "Tuffour v Attorney-General"
    "subject": str,            # display name, MUST match a SUBJECTS name
    "citation": str,           # GLR citation, MUST match the verified brief
    "other_citations": [str],  # neutral / Dennislaw citations, ONLY where confirmed
    "court": str,
    "judges": [str],           # [] if not confirmed from a checked source
    "decided": str,            # MUST match the verified brief
    "topics": [str],           # 2-5 topic tags
    "facts": str,              # material facts — MUST be non-empty
    "procedural_history": str, # "" if not confirmed
    "issues": [str],           # MUST be non-empty
    "holding": str,            # the court's decision — MUST be non-empty
    "ratio": str,              # ratio decidendi, the binding rule — MUST be non-empty
    "obiter": str,             # "" if none identified
    "reasoning": str,          # the court's reasoning in brief; "" if nothing verified
    "order": str,              # order made; "" if not confirmed
    "significance": str,       # why it matters / what to cite it for — MUST be non-empty
    "legislation": [str],      # legislation considered; [] if none confirmed
    "cases_considered": [      # [] if none confirmed; treatment in
        {"name": str, "citation": str, "treatment": str},  # {applied, followed,
    ],                         #  distinguished, referred to, overruled}
    "related_cases": [str],    # slugs of other library cases; [] ok
    "full_judgment_link": str, # real URL only; "" if none found
    "full_judgment_label": str,# "" if no link
    "sources": [str],          # sources checked — MUST be non-empty
    "verification": str,       # one-line status + month/year — MUST be non-empty
}
```

Empty-string / empty-list fields render as "not confirmed" or are omitted
by the template — they are NEVER filled with guesses. `facts`,
`holding`, `ratio` and `significance` must be grounded in the verified
brief and/or a named checked source; if a holding or ratio cannot be
grounded for a case, the draft flags that case and it is held back.

## 3. Routes and behaviour

- `GET /library` — index + search + filters in one route. Query params:
  `q` (search text), `subject` (subject slug), `court` (`supreme` /
  `appeal` / `high`, reusing the existing `court_group()` helper).
  Search matches, case-insensitively: title, citation,
  other_citations, court, judges, topics, subject, facts, holding,
  ratio, significance. Cards show title, citation, court, decided,
  topics, and the first line of `significance`.
- `GET /library/<slug>` — the full case file, sections in schema order.
  Bookmark button reuses the bookmark system with kind `"library"`
  (route extended to accept it; account page resolves it to a
  `/library/<slug>` link). Related cases link to their files.
- Empty search result — "No case file yet for that search", a link to
  GhaLII (https://ghalii.org/ — curl-confirmed 200 on 2026-11-14; the
  deeper /judgments/ URLs returned 403 to direct fetches that day, so
  the link goes to the GhaLII homepage and the label says the full
  judgments are in its judgments section), the request form, and the
  request count for that query text if any.
- `POST /library/request` — login required (existing `login_required`
  decorator). Fields: `case_name` (required), `citation` (optional),
  `notes` (optional). Stored in `case_requests`. A second identical
  request from the same account is answered "already requested"
  instead of a duplicate row. Confirmation via the existing flash
  messages. The request flow does NOT depend on the gate: any
  logged-in user may request, gated or not.
- Nav: add a "Case Library" link after "Case briefs" in `base.html`.
  Homepage: one short banner block linking to `/library`.
- Account page: when the gate is ON, one line shows Pro member vs
  Free account (with a link to `/plans` for free accounts). When the
  gate is off, no such line.

## 4. The paid gate (built now, OFF until payments connect)

- Switch: environment variable `CASE_LIBRARY_GATE`. The app reads it
  into `app.config["CASE_LIBRARY_GATE"]` (default off); a helper
  `library_gate_on()` reads the config value so tests can flip it
  without restarting. Setting `CASE_LIBRARY_GATE=on` in Render is the
  one switch that gates the library. No code change, no redeploy of
  new code, is needed to flip it.
- Pro marker: a new table `pro_access (user_id UNIQUE, granted_at)`.
  `user_is_pro(user_id)` returns True when a row exists. Rows NEVER
  expire in v0.3.4 — expiry comes with the subscriptions/payments
  work, and that limit must be stated in the code comment and README.
  No UI grants pro access in v0.3.4; rows are inserted by direct DB
  write (and later by the payment webhook).
- Gate ON behaviour:
  - `/library` index stays open to everyone (discovery), with each
    card marked Pro and an upgrade note for non-Pro visitors.
  - `/library/<slug>` for non-Pro visitors shows a teaser ONLY:
    title, citation, court, decided, topics — and a "full case files
    are for Pro members" note linking to `/plans`. NO facts, holding,
    ratio, or any other file content. Pro members see the full file.
  - Logged-out visitors are treated as non-Pro.
- Gate OFF behaviour: everything open to everyone, no Pro markings,
  no upgrade notes. The gate code paths MUST still be tested with the
  config flipped (see §6).

## 5. Database additions (both schemas, additive only)

```sql
CREATE TABLE IF NOT EXISTS pro_access (
    id INTEGER PRIMARY KEY AUTOINCREMENT,  -- SERIAL in PostgreSQL
    user_id INTEGER NOT NULL REFERENCES users(id),
    granted_at TEXT DEFAULT (datetime('now')),  -- TIMESTAMPTZ DEFAULT NOW() in PG
    UNIQUE (user_id)
);
CREATE TABLE IF NOT EXISTS case_requests (
    id INTEGER PRIMARY KEY AUTOINCREMENT,  -- SERIAL in PostgreSQL
    user_id INTEGER NOT NULL REFERENCES users(id),
    case_name TEXT NOT NULL,
    citation TEXT NOT NULL DEFAULT '',
    notes TEXT NOT NULL DEFAULT '',
    created_at TEXT DEFAULT (datetime('now'))  -- TIMESTAMPTZ DEFAULT NOW() in PG
);
```

Existing tables untouched. `?` placeholders as usual (`db.py` translates
for PostgreSQL).
